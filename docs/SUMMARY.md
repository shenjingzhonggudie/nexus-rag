# 能力边界与待办

当前命令、有效配置和实测数据统一见 [README](../README.md)；模块接口与数据约束见 [PROJECT_LAYOUT](PROJECT_LAYOUT.md)，标注维护见 [data/README](../data/README.md)。本页仅记录尚未解决的边界。

## 当前边界

- 已实现文本/Markdown 加载、分块、BM25、hashing/BGE 向量检索、排名融合、原文抽取、引用、HTTP/CLI 和检索评测。BGE 是已接入的可选实现，离线运行依赖本地模型文件。
- `rerank` 当前执行加权排名融合，没有 cross-encoder。`llm.provider=none` 返回第一名块原文；`openai_compatible` 尚未实现。
- 拒答依靠英文标识符与词语覆盖率规则，难以区分“主题相关”和“证据足够”。正常题误拒与无答案题漏拒都需要检查。
- 开发集v2按回答要点的必要证据覆盖判分，每段须严格超过50%；Recall/MRR衡量检索覆盖，未验证最终回答正确性。证据标注由AI辅助逐题核对，尚无独立人工验收。开发集已参与反馈，不能作为未见问题上的独立结论；历史实验保持原格式与成绩。
- 索引逐文件写入，缺少整库事务及完整性哈希校验。embedding 使用进程全局状态，当前接口不支持多模型索引间的独立状态。

## 已知待办

| 项目 | 当前问题与下一步 |
|---|---|
| 标注工具坐标 | `section_index.py`、`gen_queries.py`、`build_skeleton.py` 直接规范化原始文件，与建库前的加载清洗不一致；其偏移不能直接用作当前标注，需要统一处理链 |
| 模型回归 | pytest/CI 未运行真实 BGE；增加可选的本地模型集成验证，并明确缓存与版本条件 |
| 证据与拒答 | 固定人工核验样本，检查返回证据是否足以回答；在开发集上调整规则，再用未参与选择的新题评估 |
| 评测输出 | 默认 final_k=5，当前仍输出 @6～10；应限制展示范围或显式区分粗召回与最终候选指标 |
| 分块配置 | heading 使用内部400/300/0常量，配置中的 chunk_size/overlap 不生效；recursive 暂走 fixed，需要明确实现或限制配置 |
| 安装元数据 | 本轮发现源码版本与本地 editable 包元数据版本不一致；修改包元信息后核对安装状态 |

生成模型、独立重排模型、增量索引、新文件格式和服务部署能力仍需各自实现与验证。是否增加这些功能，应由具体使用需求和测量结果决定。
