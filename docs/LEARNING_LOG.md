## 关键设计变化

- **数据契约先于算法。** 领域对象负责结构化数据，配置层校验外部输入，CLI/HTTP 负责展示。这样更换检索策略时不必同时改写所有入口。
- **标注与分块解耦。** 超长小节再切曾打破“小节序号等于块索引”的假设。答案后来改标文档字符区间；坐标须基于 `normalize_text(load_file(path).text)`，语料或清洗规则变化后仍需复核。
- **重排实现调整。** 旧版用与 dense 相同的点积重新排序，会覆盖融合结果。后来由 rerank 承担加权排名融合，删除 weighted_fuse 的重复实现；这不表示接入了独立重排模型。
- **拒答从判空扩展为规则。** dense 通常仍会返回候选，因此增加实词覆盖率和语料外英文标识符检查。规则仍可能漏拒或误拒，候选非空、词语匹配都不证明存在充分答案。
- **评测数据逐步替换。** 合成语料后来被公开文档替换，并引入只看标题出题的样本。报告按来源分组，但两组的题型构成不同，不能把差异全部归因于问法，也不能直接代表真实用户表现。
- **回答能力显式限定。** 离线链路先采用最高分块原文抽取；未实现的远程生成配置显式报错，避免静默降级造成能力误解。

## 保留的踩坑经验

1. **往返相等不够。** 序列化两端可能对称地写错；测试还需独立期望值、字段/类型检查和真实边界输入。断言原对象、漏注入输入等错误曾让测试通过却没有验证目标行为。
2. **缺失、None 和空值要分清。** `.get(k, default)` 只处理缺失；可变默认值使用 default_factory，必填校验与字段默认值保持一致。
3. **输入可注入，测试才易隔离。** argv/environ 显式传入，环境变量修改使用 monkeypatch，避免失败后的清理遗漏影响其他测试。
4. **路径和文本坐标必须一致。** build root 改变会改变 doc_id；标注、加载和切分若使用不同清洗结果，区间检查和检索命中会失真。
5. **先确认消融真的改变了变量。** 曾出现 baseline 与 no_rerank 都关闭重排的无效对照。默认值或实现变化后，重新检查各组实际配置；单路实验也要避免引入另一路信号。
6. **分数含义不能混用。** 排名融合分不等于匹配概率；小节区间命中不等于回答正确。拒答要同时报告无答案题漏拒和有答案题误拒。
7. **先核对数据，再解释指标。** 曾发现无答案题实际有证据、重复 query、同词但无关的跨文档配对。标签、来源和版本应与报告一起记录，不能用调参掩盖错误标签。
8. **诊断要区分层次。** 测试收集失败、断言失败、解释器损坏、安装失败分别处理；不可见字符和文件内容用实际读取确认，构造示例不能代替原文件证据。
9. **安装元数据与源码版本可能不同。** editable 安装后修改源码版本，不会自动刷新 dist-info；重新安装时还需核对构建依赖，不能仅凭 --version 判断打包状态。

## 环境事故

2026-10-05 曾出现源码及虚拟环境文件行尾 `t` 丢失，导致语法错误。根因是批量清理行尾空白时，正则字符类把 `[ \t]` 写成了 `[ t]`：制表符没被删除，反而吃掉了行尾字母 `t`（`import` → `impor`、`print` → `prin`），致语法错误。

当时修复项目文件并重建虚拟环境后恢复运行。留下的经验是：批量修改先限定范围、检查差异；可再生的环境优先重建，代码和人工标注应保留可恢复版本。事故时缺少 Git 提交，增加了定位与回退成本。

## 2026-10-25 / 融合与模型重排分开

变化与原因：把加权排名融合迁入 fusion.py，由 retrieval.fusion_method 选择；rerank.py 改为独立 query-document CrossEncoder，始终默认仅加载本地模型。初次接入阶段 rerank.enabled 默认关闭；本轮按用户直接安装使用的要求改为默认启用。两路各召回 top_k，融合去重取 top_k，重排后才取 final_k；拒答仍使用原有 BM25 match_score。旧 rerank_enabled 只警告并迁移融合方式，不改变独立模型开关；消融 no_rerank 更名 rrf，六组显式设置 RerankConfig(enabled=False)，保持只比较召回与融合。

验证：初次接入且默认关闭阶段全量自动测试通过（453 passed），当时另用完全离线的小型随机模型核验真实CrossEncoder推理与fusion→rerank轨迹；本轮安装权重并改为默认启用后，按用户要求未再运行测试、测速、模型推理或评测。未重跑开发集或盲测，原数字保留为历史仅融合成绩。此前已刷新editable安装元数据至源码版本1.0.0。遗留：预训练重排模型质量与耗时尚无本轮实测，后续比较须绑定模型版本、候选预算和独立评测配置，见 SUMMARY。

## 2026-10-26 / 真实重排的固定配置对照

变化与原因：按新授权，在同版本、同索引和冻结v2标注上只开关CrossEncoder，开发248题和留出回归62题共620次查询；保存有效配置、模型修订、输入哈希、融合候选及最终排序，保留历史归档。

验证：真实模型完成全部查询，独立字符集合算法复算全部前缀与汇总一致，且两组候选和拒答相同。开发集证据覆盖改善，留出回归@5小幅提高但@3下降；拒答无改善，本机CPU平均每查约11秒。未重跑完整pytest，未验证回答语义正确率，也不称新的独立盲测。完整结果见[本轮归档](../experiments/rerank-2026-10-26-run1/README.md)。

## 2026-10-26 / 复核默认值与评测范围

变化与原因：融合公开函数的默认α统一为0.7；题型配比偏差真正进入warnings，使strict按约定失败。补明消融为203道可答题的全局宏平均、external缺无答案样本、CI及v1/v2边界，忽略快速开始的演示产物。生产流水线原已显式传0.7，历史实验和冻结答案未改。

验证：用户此前复测默认启用版为453 passed in 26.91s；本轮新增5个回归用例后完整套件为458 passed in 15.36s，默认配置仍启用重排，自动测试使用替身而非预训练质量评测。实际题集普通检查退出0、strict退出1，multi_block配比警告得到确认。
