# 任务：为中文检索评测集写 40 条「用户视角」问题

> 历史出题任务书：记录第一批标题出题过程，该批已被后续批次替换。本文件不代表当前待办，也不证明问题具有真实用户代表性。当前题集说明见 [data/README](../data/README.md)。

## 背景（一句话）

已有问题是读过正文后写的，可能更容易使用原文措辞。本批尝试只根据小节标题生成问题候选，
用于比较不同出题来源的检索表现；候选是否可回答，需要后续核对正文。

## 铁律（必须遵守）

1. **只看本文件给出的标题**。不要打开、搜索、推断任何文档正文；如果你能访问项目
   文件，也**不要**去读 `data/raw/` 下的内容。
2. **不要猜测正文写了什么**。你只能根据标题的字面意思推测"这一节大概在讲什么"。
3. **允许写出"可能答不上"的问题**。如果标题信息不足以判断，标记 `skip`——这不是失败，
   而是我们想统计的"标题信息量"。
4. 不要为了保险而把标题原样改写成问句（那是无效样本，我们已有 39 条了）。

## 出题要求

### 数量与类型

为上述 id **各写 1 条**（允许 skip），共 40 条。类型二选一：

- **`direct`（约 20 条）**：可以使用标题里的技术术语（如「节点心跳」），但**必须重造句式、
  补充场景**，不能把标题直接改成问句。
  例：标题「节点心跳」→ `Kubernetes 里节点的存活状态多久上报一次？`
- **`paraphrase`（约 20 条）**：**不出现标题里的技术术语**，改用同义表达或描述现象。
  例：标题「节点心跳」→ `集群怎么判断某台机器是不是已经掉线了？`

### 硬性约束

1. 长度 **10~35 个汉字**（含标点不超过 40 字符）；
2. 复用限制：
   - **`paraphrase`**：禁止出现标题里连续 **4 个汉字**及以上的片段；
   - **`direct`**：禁止出现标题里连续 **6 个汉字**及以上的片段（即不能整句照搬）；
   - 两种情况都禁止把标题**原样改成问句**。
   例：标题「非事务批量删除」→
   direct 可写 `一次删几十万行数据时，怎么避免大事务把数据库拖垮？`；
   paraphrase 可写 `要清掉大量历史数据，有没有不锁表的办法？`；
   两者都不能写 `非事务批量删除怎么用？`。
3. 每条问题必须是**一个**问题，不要并列两个问句；
4. 不要出现"本小节""这段内容""如下图所示"之类的元指代；
5. 用**真实用户会说的话**，可以口语化，不要写成考试题。

### 什么时候 skip

出现以下情况直接标 `skip` 并写原因：

- 标题不足 4 个字且看不出具体主题（如「设计」「下一步」）；
- 标题是导航/示例/罗列性质（如「下一步」「执行 `CREATE TABLE` 语句」）；
- 你能想到的任何问题都只能靠猜正文，且猜错的概率很高。

**预计 skip 3~6 条是正常的**，不要强行填满。

## 输出格式

只输出一个 JSON 数组，不要包 markdown 代码块之外的解释：

```json
[
  {"id": 0, "type": "paraphrase", "query": "容器之间要互相通信，底层是谁在负责搭这套网络？"},
  {"id": 8, "skip": true, "reason": "标题只有「设计」两个字，无法判断是哪个组件的设计"},
  {"id": 25, "type": "direct", "query": "v-if 和 v-show 在渲染开销上有什么区别？"}
]
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 对应上表的 id |
| `type` | 非 skip 时必填 | `direct` 或 `paraphrase` |
| `query` | 非 skip 时必填 | 问题文本，10~35 汉字 |
| `skip` | 否 | 布尔，true 表示放弃这条 |
| `reason` | skip 时必填 | 一句话说明为什么放弃 |

## 自检清单（提交前逐条过一遍）

- [ ] 40 个 id 都出现且只出现一次
- [ ] 没有一条包含标题里连续 4 个汉字以上的片段
- [ ] `paraphrase` 里没有出现标题的技术术语
- [ ] 每条 10~35 汉字，且只有一个问号
- [ ] skip 的条目都写了 reason
- [ ] 没有读正文、没有搜索项目文件（除本文件）

## 我们会怎么校验

1. 用脚本检查：id 覆盖、长度、类型配比、是否复用标题长片段；
2. 用这些 query 跑检索，统计 `recall@1 / recall@3`，和"读正文出的题"对比；
3. **答不上的问题不会被认为是你的错误**——那正是我们要测的"标题信息量不足"，
   它会让评测更接近真实用户。
