# 标注格式与评估契约

本文件规定新的留出题（holdout）标注应当怎么写，以及这些标注将如何被使用。
不含任何实现细节、算法说明或方法评价。

## 1. 输入文件

| 文件 | 内容 | 使用约定 |
|---|---|---|
| `corpus.jsonl` | 固定知识库全文，每行 `{doc_id, text, sha256}` | **判断证据的唯一依据** |
| `sections.jsonl` | 各文档的小节清单，每行 `{doc_id, section, start, end}` | 供选题、定位区间 |
| `old_queries.jsonl` | 既有开发题，每行 `{id, query}` | **仅审核者用于排除原题与近似改写；出题者不读取本文件** |
| `corpus_manifest.json` | 哈希、导出时间、代码版本、导出流程 | 版本核对 |

`old_queries.jsonl` 只含题干，不含任何答案、系统输出或分数。

## 2. 输出格式

一个 UTF-8 JSON 数组，每个元素是一条标注：

```json
[
  {
    "id": "h_0001",
    "query": "节点失联后，集群靠什么机制在有限时间内判定它已下线？",
    "type": "paraphrase",
    "answers": [
      {
        "doc": "k8s/content__zh-cn__docs__concepts__architecture__leases.md",
        "section": "节点心跳",
        "start": 6932,
        "end": 7470
      }
    ],
    "source": "holdout"
  }
]
```

## 3. 字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 是 | string | 形如 `h_0001`，批次内唯一，此后**不可变**（改题干或答案也保留同一个 id） |
| `query` | 是 | string | 自然语言问题，非空 |
| `type` | 是 | string | 取值见第 4 节 |
| `answers` | 是 | array | 答案小节列表；**空数组 `[]` 表示无答案题**（见第 7 节） |
| `answers[].doc` | 是 | string | 文档标识，**必须与 `corpus.jsonl` 的 `doc_id` 完全一致**，逐字符相等 |
| `answers[].section` | 是 | string | 该区间所属小节的标题，取自 `sections.jsonl` 中与区间对应的 `section` 值 |
| `answers[].start` | 是 | int | 区间起点（**含**） |
| `answers[].end` | 是 | int | 区间终点（**不含**），必须 `end > start` |
| `source` | 是 | string | 来源标记，本批统一填 `holdout`（见第 6 节） |

## 4. 允许的类型

| `type` | 含义 | `answers` 数量 |
|---|---|---|
| `direct` | 直接用文档中的术语提问 | 恰好 1 个 |
| `paraphrase` | 换说法、不照抄原文术语 | 恰好 1 个 |
| `multi_block` | 答案分散在 2~3 个不同小节，需综合 | 2~3 个 |
| `cross_doc` | 需要跨文档对比才能回答 | 2~3 个，且 `doc` 不同 |
| `no_answer` | 固定知识库中没有能支撑该问题的内容 | **必须为 `[]`** |

除 `no_answer` 外，`answers` 不得为空。

## 5. 区间坐标规则

**坐标系**：`corpus.jsonl` 中该文档的 `text` 字段，即 `text[start:end]` 能原样取出该小节。

| 规则 | 说明 |
|---|---|
| 单位 | **Unicode 码点**（Python `str` 的下标单位），不是字节、不是词数、不是“字数” |
| 边界 | **左闭右开** `[start, end)`；`end` 位置的字符不属于该区间 |
| 范围 | `0 <= start < end <= len(text)`，越界即非法 |
| 起点 | 通常是小节标题行的第一个字符（`#`） |
| 终点 | 通常是下一小节标题行之前的最后一个字符之后，或文档末尾 |
| 获取方式 | **必须程序计算**（对 `text` 做标题切分），不得手工估算或从别处抄写 |
| 自检 | `text[start:end]` 应当以该小节的 `##` 标题行开头 |
| **无 `##` 标题的文档** | 整篇作为**一个**区间 `[0, len(text))`，此时 `section` 为**空字符串**。`sections.jsonl` 里只有 2 篇属于这种情况，其 `start == 0` 且 `end == 文档长度` |

**注意**：不要用原始 Markdown 文件的字符偏移。`corpus.jsonl` 的 `text` 是规范化后的文本，与原始文件长度不同。`doc_id` 也同样以 `corpus.jsonl` 为准。

## 6. `source` 的含义

`source` 标记出题视角，只用于分组统计，不参与任何判定：

| 值 | 含义 |
|---|---|
| `internal` | 读过正文后出题（答案保证能被所标小节回答） |
| `external` | 只看小节标题、不看正文出题（更接近真实用户问法） |
| `holdout` | 本批留出题：出题者读过 `corpus.jsonl`，但独立于既有开发流程 |

本批统一填 `holdout`。

## 7. 评估契约

**① 唯一依据是固定知识库。**
判断“证据是否足以回答”时，只看 `corpus.jsonl` 提供的内容。**不得用模型自身的常识、预训练知识或外部资料补齐**语料中没有写明的信息。

- 若语料中没有相关内容 → 该题应为 `no_answer`（`answers: []`）
- 若语料只提到相关概念、但没有回答问题所问的具体点 → 同样应为 `no_answer`
- 不得因为“这个问题在现实中确实有答案”就给出 `answers`

**② 答案必须能在所标区间内找到。**
`text[start:end]` 这段内容应当直接包含回答问题所需的信息。不能标一段“主题相关但没有回答问题”的文字。

**③ 系统当前为抽取式输出。**
系统从语料中选取片段作为答案依据，不会改写、综合或补写原文没有的内容。因此：

- 题目应当能由语料中的**明确表述**支撑
- 需要跨段落推理才能得出、而原文并未明说的结论，不适合作为 `direct` / `paraphrase` 题
- 如果确实需要多处信息合并，请用 `multi_block` 并如实标注全部相关小节

**④ 无答案题同样有价值。**
`no_answer` 用来检验“证据不足时系统是否仍强行作答”。这类题应当**确实在语料中找不到支撑**，而不是“很难找到”。选题时应先确认对应主题在语料里存在，再把问题指向语料没有覆盖的具体点。

## 8. 提交前自检清单

- [ ] `doc` 与 `corpus.jsonl` 的 `doc_id` 逐字符一致
- [ ] `start` / `end` 由程序计算，`text[start:end]` 以 `##` 标题行开头
- [ ] `end > start` 且不越界
- [ ] `type` 与 `answers` 数量匹配（见第 4 节）
- [ ] `no_answer` 的 `answers` 为 `[]`
- [ ] `id` 批次内唯一
- [ ] 全部题干不读 `old_queries.jsonl` 即可完成（该文件仅供审核者去重）
