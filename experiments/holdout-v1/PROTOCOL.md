## 当前项目事实与本轮范围

2026-10-23 现场读取：项目在 `C:\Users\王佳浩\Desktop\项目`；现有 qrels 共 248 条（200 条有答案、48 条无答案）。文档记录其中 30 条为新增的同领域困难负例。这批已被用于观察系统行为的题保留作开发集，不再包装成未见测试集。

现有 CLI 已支持 `eval --qrels ... --out ...`，无需为了本轮验收先新增 split 字段。source 表示出题来源，不能拿它兼作 dev/test 划分。

本轮评估固定知识库上的新问题，不宣称评估未知领域泛化。开发者可以使用完整知识库建索引；需要隔离的是测试问题、标注及测试反馈。

先做一个约 60 题的首轮集：约 40 条可回答问题、20 条同领域无答案问题；质量优先，审核不足不凑数。它是初步独立评估，不代表生产可靠性认证。

## 分工与顺序

1. 原开发聊天：只准备输入包，随后只用开发集修改系统。
2. 全新出题聊天：只看净化的输入包，不继承开发历史，产出候选。
3. 另一个全新审核聊天：独立核验证据，决定哪些候选成立，然后封存。
4. 你保管测试题。系统完成后固定版本，再把第四段指令发给审核聊天验收。

同一种模型开新聊天也可以；换品牌或换模型不是独立性的保证。不要把整个开发聊天转发给出题者，也不要给它项目 AGENTS、系统规则、调参记录、现有评测报告或失败样本分析。

## 指令一：发给原开发 agent，准备输入包

```text
你负责为一个独立出题 agent 准备输入包，本任务不出测试题、不运行测试集、不修改检索或拒答逻辑。

项目：C:\Users\王佳浩\Desktop\项目
输出根目录：C:\Users\王佳浩\codex\2026-10-23\new-chat\outputs\rag-holdout
仅向其中 input 子目录写入输入资料；不要覆盖已有文件，若已存在先核对版本。

先读项目 AGENTS.md 与现有评测加载器，按实际文件工作，不靠 README 猜测。

导出：
1. corpus.jsonl：固定当前知识库的规范化文本，每行包含 doc_id、text、sha256。文本必须使用与建库及标注一致的 load_file(...).text → normalize_text(...)；不改变顺序、不自行删除空白。doc_id 与现有 Chunk.doc_id 一致。
2. sections.jsonl：各文档实际小节的标题、start、end，坐标对应 corpus.jsonl 的 text，字符区间左闭右开。程序计算，禁止手数。
3. old_queries.jsonl：现有开发题的 id、query，仅交审核者用于排除原题与近似改写，不包含系统输出或分数；出题者不读取这个文件。
4. FORMAT.md：只写 qrels 的字段、允许类型、区间坐标规则及 source 含义，并说明评估契约：仅以固定知识库为依据判断证据是否足以回答，不能用模型常识补齐；当前为抽取式输出。不要复制项目 AGENTS、内部算法或方法优劣结论。
5. corpus_manifest.json：语料 doc_id、文本哈希、导出时间、项目代码版本及导出流程说明。

输入包不包含项目源码、模型配置、索引、检索结果、分数、拒答规则、旧评测报告或调参记录。
只验证导出的一致性、文档数量、区间合法性和哈希。不要生成新题。
完成后只报告输入包路径、文档数量和校验结果。
准备完输入包后，本开发聊天不再读取 rag-holdout 下 candidate、sealed 或 audit 中的题目、标签和报告。在最终验收之前，只使用现有开发题进行修改和选择配置。
```

## 指令二：发给全新出题 agent

```text
你是独立测试题作者。本任务只生成候选题与标注，不运行被测系统，不做系统调优。

唯一项目资料输入：
C:\Users\王佳浩\codex\2026-10-23\new-chat\outputs\rag-holdout\input
输出：
C:\Users\王佳浩\codex\2026-10-23\new-chat\outputs\rag-holdout\candidate

仅读取输入目录中的 corpus.jsonl、sections.jsonl、FORMAT.md、corpus_manifest.json；不读 old_queries.jsonl，去重由审核者完成。不要浏览项目仓库、其他聊天、系统规则、索引、分数、拒答判据或历史失败记录。可以编写只处理输入语料与标注的辅助脚本。外部知识只能帮助理解，不能作为知识库有答案的依据。

请基于固定语料生成约 60 道新题：
- 约 40 道明确可回答，覆盖自然改写、多段取证及部分跨文档问题；题目应自然、有实际信息需求，不为了配比制造牵强组合。
- 约 20 道同领域但语料缺乏所需信息的问题；应存在相关术语或主题，不能主要依赖引入陌生技术名制造无答案。
- 候选内部避免简单改写或同一事实关系的套壳题；有共同事实关系的题记录 family_id，便于审核者与旧题检查交叉。

可回答题：
逐项写出回答要点、支持每个要点的原文引文及位置；证据必须能支持问题要求的对象、条件和范围。沿用既有答案小节区间格式，区间从输入文本程序提取并校验，另存最小支撑引文。单纯主题相关不够。

无答案题：
说明缺失的是哪个信息；列出查找过的关键词、别名、文档范围、最相关但不足以回答的原文；考虑其他文档能否提供答案，或多处证据能否合理推导答案。不能因为一个小节没写、关键词没搜到，或自己的常识不知道，就宣称全库无答案。无法充分确认的标 pending，不能进入最终集。

标签规则：
1. 只有确认语料无法支持回答时才使用 type=no_answer、answers=[]。
2. 问题前提错误但语料能明确纠正，不能直接算无答案，应给出纠正依据。本轮错误前提题默认进入扩展集，避免把纠错与拒答混成一种行为。
3. 部分可回答题、纠错行为题先放 challenges.jsonl，说明受支持与不受支持部分，不混入本轮二元拒答成绩；它们不占上述主集的数量目标。
4. 不增加现有加载器不认识的 type。source 沿用含义：读正文出题应为 internal；独立出题不等于 external。独立角色与题型细分记在旁表。

输出：
- qrels.candidate.json：符合现有格式的 JSON 数组；新题 id 使用 h_ 前缀。
- evidence.jsonl：每题的 id、family_id、题型细分、答案要点、引文、文档和区间；无答案题额外包含缺失点及检索核验记录。
- pending.jsonl：待定题与原因。
- challenges.jsonl：可选的部分回答、纠错等扩展题。

不要调用被测 RAG，不根据它是否答对选择候选。少于目标数量也如实报告，不凑数。
最后只汇报数量、类别、待定数量和输出路径，不在聊天回复中展示具体试题、标签或引文。
```

## 指令三：发给另一个全新审核 agent

```text
你是独立标注审核者；请先自行检查证据，再对照作者理由，避免只确认作者结论。

允许读取：
C:\Users\王佳浩\codex\2026-10-23\new-chat\outputs\rag-holdout\input
C:\Users\王佳浩\codex\2026-10-23\new-chat\outputs\rag-holdout\candidate
允许写入：同一 rag-holdout 根目录下的 audit 与 sealed 子目录。
不要读取被测系统的实现、拒答规则、模型配置、索引、历史分数或输出。不要运行被测系统。

逐题核验：
1. 可回答题：证据是否支持题干的全部必要条件和结论；核对实际引文、文档、区间，排除仅主题相近的标注。给出合格的参考回答要点。
2. 无答案题：独立查找全库可能支持回答的文档，考虑别名、改写和跨文档推导。不能用被测 RAG 未命中作为无答案证据。充分性无法确认就记 pending；不要声称读完实际未读的文档。
3. 错误前提可被语料纠正、部分可回答的题，不强塞入 no_answer。需要行为评审的题保留在 challenges 文件，不混入主集。
4. 与开发题、候选题逐字去重，并检查语义近重复和同一事实关系的套壳题。标记 family_id 与潜在交叉；有争议的先排除。
5. 使用与输入相同的规范化文本与坐标；保留合法 type 与 source 含义；校验 id 唯一、区间、引用子串及最终题目覆盖范围。

独立审查通过后生成：
- audit/review.jsonl：每题的通过/修订/排除/待定结论、实际核验范围、引文依据及理由。
- sealed/qrels.test.json：只有核验通过的主集，不要求凑满 60 条。
- sealed/metadata.jsonl：每题的类别、family_id、参考回答要点及证据说明，保留困难无答案子类。
- sealed/challenges.jsonl：扩展行为题，单独保存。
- sealed/manifest.json：最终题集、旁表和固定语料的 SHA-256、题量与各类数量、版本、封存时间及预定评测规则。

封存前先约定报告口径：正常问题误拒率；各类无答案问题的正确拒答数/总数；可回答题 recall@k、MRR；单独人工检查证据充分性。不要将区间命中率解释成最终回答正确率。
从合格题中预先固定一个人工核验子集，验收时检查返回证据是否充分；不要等看到系统表现后再挑有利样本。

审核不能参考系统表现：不得因为系统答错就删题，也不得为了降低分数保留错误标签。封存后发现标注错误时，保留修订日志并递增数据版本，不能静默改答案。
完成后只报告路径、数量、类别、排除/待定数量和校验结果，不在聊天回复里展示具体题目或答案。
未经我明确发出“开始最终验收”的后续指令，不运行系统、不输出测试分数。
```

## “封存”到底指什么

封存包含文件版本固定、开发阶段不读题、不根据测试成绩修改系统。哈希能核对文件有没有变，不能阻止文件被读取；新聊天也不自动创建文件权限隔离。若各 agent 共享全盘读取权限，本方案属于流程隔离；需要更强保证时，把 sealed 文件交给开发 agent 无权访问的独立账户或存储保管。

现在不必给所有困难题设置“必须通过”的门槛；先如实测清边界。测试集参与系统选择会让成绩偏乐观，原则可参考 scikit-learn 官方的 [Data leakage 说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。
