## 固定输出重评

原报告只读取 `query`、`retrieved`、`refused` 三个字段，不使用旧命中、旧分数、旧题型或旧无答案标签。62道题逐一精确匹配，无丢题；A的198个、B的204个不同检索块均解析成功，逐个核验其字符切片与内容指纹。两份索引的块表相同，正文清理、分块及坐标代码与原实验版本无差异。

前k块按文档取区间并集，每段证据的覆盖率以该段长度为分母，必须严格大于50%；恰好50%不命中。重复不叠加、缺口不补齐、不同文档不拼接；一个要点的所有必要证据均须达标。Recall先按题求命中要点比例再平均；前缀MRR取首次支持任一要点的前缀排名倒数，不要求全题完整。

| A：BGE＋加权融合 | 43 | 0.661 | 0.890 | 0.913 | 0.8605 | 36/43（83.7%） | 0/17 |

2道待复核题不计主Recall/MRR及拒答分母，保守整题指标将其一律视作未完整覆盖，分母为45：A为36/45（80.0%），B为34/45（75.6%）。两组在43道完整可答题上均无误拒，17道无答案题全部漏拒。首个检索块就完整覆盖全部要点的分别为24/43（55.8%）、21/43（48.8%）；不能把前5块的联合覆盖当成首块已经完整作答。

配置名称来自原归档YAML；旧JSON没有内嵌实际生效的配置快照。旧报告也没有最终回答正文，本次只能复核保存的检索内容和拒答标记，不能声称已验证实际最终回答，更不能把字符覆盖解释为语义正确率。当前每个要点只指定一组必要证据，可能存在未枚举的等价表述。

## 复现与验证

在仓库根目录、有与冻结哈希一致的原语料及本地索引时执行：

```powershell
.\.venv\Scripts\python.exe scripts/rescore_holdout.py
.\.venv\Scripts\python.exe scripts/check_holdout_regrade.py
.\.venv\Scripts\python.exe -m pytest -q
```

第一个脚本在读输出前校验冻结提交字节，核验原档实际文件、语料和块映射后重评，不调用检索模型。第二个脚本仅用标准库，以字符位置集合独立求覆盖，不调用主覆盖实现；无需本地正文或向量索引，使用已记录区间、冻结标注和原保存报告即可复核。两种实现的全部124条配置/题目记录、每个保存前缀、每项汇总均一致。
