# CrossEncoder 重排对照实验（2026-10-26）

本实验比较同一版本、同一索引上的两条流程：BM25＋BGE 召回 → 加权 RRF 融合，以及在其后增加 CrossEncoder 重排。固定全部题目、证据标注和参数，两组仅 `rerank.enabled` 不同；不根据本次结果修改标注或选择参数。生产代码版本为 `0e191f7`，runner及全部输入哈希见 [PLAN.json](PLAN.json)。

## 固定设置

| 项目 | 设置 |
| --- | --- |
| 召回 | BM25＋`BAAI/bge-small-zh-v1.5`，512维，复用 `data/index` |
| 融合 | 加权 RRF，BM25权重 α=0.7；每路最多20块，融合后最多20块 |
| 最终输出 | 5块；对照组直接截取融合前5，实验组重排融合候选后取前5 |
| 重排 | `BAAI/bge-reranker-base`；CPU；batch size 16；max length 512；仅加载本地文件 |
| 拒答 | BM25实词覆盖率阈值0.05及英文实体检查，不使用重排分数 |
| 回答 | `llm.provider=none`，返回最高分块原文 |
| 运行 | 离线、6个Torch计算线程、1个interop线程；先两份题集的融合对照，再两份题集的重排组 |

本地embedding修订为 `7999e1d3359715c523056ef9478215996d62a620`，重排模型修订为 `2cfc18c9415c912f9d8155881c133215df768a70`；各文件哈希随PLAN保存。环境为Python 3.12.10、Torch 2.14.1、sentence-transformers 6.1.0、Transformers 5.20.2，其他环境信息见PLAN。

配置快照分别见 [config.fusion_only.json](config.fusion_only.json) 和 [config.cross_encoder.json](config.cross_encoder.json)。α=0.7是本轮固定值，不表示已证明最优。加载索引时，以manifest记录的embedding模型为准，不能只看应用默认provider。

## 数据与判分

- 开发集：248题，203道可回答、45道无答案；开发题已参与反馈，按internal/external来源分别报告有答案题指标。
- 留出集回归：62题，43道可回答、17道无答案、2道待复核。该集已用于开发反馈，本轮不是新的独立盲测；待复核题保留输出，但不进入主指标或拒答分母。
- 沿用已有v2回答要点与最小充分证据，不重标题目。前k块在同一文档的字符区间取并集；一个要点的每段必要证据均须覆盖严格超过50%，要点才算命中，恰好50%不算。不同文档不拼接，重复区间不重复计数。
- Recall@1/3/5为每题已覆盖要点比例的宏平均；MRR取首次覆盖至少一个要点的排名前缀的倒数；Complete@k表示前k块覆盖全部必要要点的题目比例。无答案题报告正确拒答率，有答案题报告误拒率。

这些指标衡量返回块的证据覆盖，不是实际回答的语义正确率。题集较少、构成不同，不把两份题集间的分数差异解释为能力差异，也不据此宣称独立泛化表现。

## 记录与复核

`eval.<dataset>.<variant>.json`保存有效配置、判分口径、逐题最终chunk ID顺序、要点覆盖、拒答和指标。对应的`retrievals.*.jsonl`保存20个以内的融合候选、最终5个以内结果的分数及阶段、区间、文本哈希、阶段耗时和实际回答哈希；并非全部20个候选的模型分数。

实际回答正文和引用保存在忽略提交的`reports/rerank-2026-10-26-run1/answers.*.jsonl`，不将第三方正文写入实验归档。完整运行结束后，`COMPLETED.json`记录输入未变、配对候选及拒答一致的检查和产物哈希；另以独立字符位置集合方法复算覆盖及主指标，复核记录随结果保存。

## 限制与耗时解释

- 两组使用相同召回候选；重排无法补回未进入融合候选池的证据。拒答在重排前独立计算，因此两组拒答结果预期一致，不能把排序改善解释为拒答能力改善。
- 模型输入的问题与正文合计最多512 token，超长输入会截断；证据评分仍针对返回的整个块。覆盖成绩不证明模型实际读取了块中的每一处证据。
- 这是一轮顺序执行的CPU实测，记录当次环境和耗时，不作为稳定性能基准。trace总耗时不包含加载索引、判分和写文件；端到端时间另见报告。
- 原始报告的`experiment.started_at`写入的是整轮实验开始时间，不是各块独立起点。`latency.cold_ms`是各块首个查询的阶段耗时；`first_query_is_true_cold`不能解释为完整冷启动证明：融合对照首查首次加载embedding，重排组开发集首查复用已加载embedding并首次加载重排模型，后续题集复用模型。运行顺序影响耗时解释。

## 复现

```powershell
.\.venv\Scripts\python.exe scripts/run_rerank_experiment.py --out experiments/rerank-reproduction --threads 6
```

输出目录必须不存在，不能覆盖本次归档。脚本忽略外部`RAG__`配置覆盖，固定离线模式；先核验v2证据、语料与索引字符坐标，再运行两组。复现前应核对PLAN中的源代码版本、runner哈希、包版本、模型修订和输入哈希；不同环境或权重应保存为另一轮记录。
