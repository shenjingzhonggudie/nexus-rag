# 缓存穿透与雪崩

## 缓存穿透

缓存穿透指查询一个根本不存在的数据，缓存和数据库都没有命中，请求直接打到数据库。攻击者可以构造大量不存在的 key，绕过缓存层持续冲击数据库，因为不存在的 key 永远不会被缓存，每一次查询都穿透到底层存储。穿透的危险在于它绕过了缓存的设计初衷，让数据库暴露在无效查询的洪流之下。识别穿透要看数据库的查询分布：如果大量查询集中在不存在的 key 上，且这些 key 呈现随机或递增特征，基本可以判断是穿透攻击或业务逻辑缺陷。

## 穿透的解法

缓存穿透有两种常见解法。一是缓存空值：把不存在也作为一个结果缓存起来，设置较短的过期时间，这样后续相同 key 的查询能直接命中空值缓存而不再打库。空值缓存的问题是会占用缓存空间，如果攻击者构造海量不同 key，空值缓存本身也会被打爆，因此通常要限制空值缓存的数量或过期时间。二是布隆过滤器：在缓存之前先判断 key 是否可能存在，布隆过滤器用位数组和多个哈希函数高效判断成员关系，能拦截大部分非法 key。布隆过滤器的特点是可能存在误判，但绝不漏判，适合作为前置防线。

## 缓存雪崩

缓存雪崩指大量缓存 key 在同一时间集中过期，请求瞬间全部落到数据库，导致数据库压力骤增甚至宕机。雪崩的根源是过期时间的一致性：如果一批 key 在同一个时间点写入、设置了相同的过期时间，它们就会在同一时刻集体失效。解决思路是打散过期时间，在基础过期时间上叠加一个随机值，让 key 的失效时刻分散开来，避免集中过期。对于必须同时更新的数据，可以用双缓存或永不过期加异步更新的策略，把失效压力转移给后台任务。

## 缓存击穿

缓存击穿与雪崩不同，指的是单个热点 key 过期，大量并发请求同时穿透缓存去数据库查询同一个数据。击穿的破坏力集中在单点：热点 key 往往是访问量极大的数据，它失效的瞬间，所有请求都打到数据库的同一条记录上。解法是对重建缓存的操作加互斥锁，只有一个请求去数据库查询并重建缓存，其余请求等待结果。互斥锁的关键是设置合理的等待和超时，避免锁本身成为新的瓶颈。击穿和雪崩常被混淆，但一个是单点失效，一个是集体失效，应对策略也不同。

## 三者辨析

穿透、雪崩、击穿三者都表现为数据库压力突增，但触发条件和解法各不相同。穿透是查不存在的数据，根因是数据本身不在库里，解法是空值缓存和布隆过滤器；雪崩是大量 key 集中过期，根因是过期时间一致，解法是打散过期时间；击穿是单个热点 key 过期，根因是热点集中，解法是加锁重建。定位问题时要先分清属于哪一类，因为它们的解法不能互换。把击穿当成雪崩去处理，或者反过来，都会事倍功半。三者的共同点是都绕过了缓存本应承担的保护作用，让数据库直接承受压力。

## 布隆过滤器的原理

布隆过滤器是一种空间效率极高的概率性数据结构，用于判断一个元素是否可能存在于集合中。它维护一个位数组和多个哈希函数，插入元素时把元素经过各哈希函数映射到的位置都置 1，查询时检查这些位置是否都为 1。如果有一个位置是 0，元素一定不存在；如果都为 1，元素可能存在，但可能是哈希碰撞造成的误判。布隆过滤器的优点是内存占用极小、查询极快，代价是存在误判率且不支持删除。在缓存穿透防护中，它用来在缓存之前快速拦截不存在的 key，误判的代价只是多查一次数据库，可以接受。

## 热点 key 的治理

热点 key 是缓存系统里访问最集中的少数数据，它的失效会引发击穿，它的更新会引起大量请求竞争。治理热点 key 的核心是分散压力：可以把热点 key 复制成多份，用不同的 key 分散到不同的缓存节点；也可以在应用层做本地缓存，让热点数据在进程内就命中，不必每次都到分布式缓存。对于热点 key 的更新，要避免所有请求同时去数据库重建，用互斥锁或异步刷新保证只有一个重建者。热点 key 的识别依赖监控，从访问频率的分布中找出头部数据，针对性地做分散和预热。

## 缓存稳定性体系

缓存穿透、雪崩、击穿的防护不是孤立措施，而是一个稳定性体系的组成部分。这个体系包括：缓存与数据库的一致性策略、过期时间的科学设计、热点数据的识别与治理、以及针对各类失效的防护手段。单点防护只能解决单一问题，体系化的防护才能应对复杂的真实场景。监控和演练同样重要：定期模拟缓存失效、观察数据库压力变化，验证防护措施是否真的有效。缓存稳定性不是一劳永逸的，随着业务和流量模型变化，防护策略也要持续演进。
